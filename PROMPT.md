# Project 1990 — Улучшенный промпт для разработки

Используй этот документ как основной бриф при каждом этапе работы.

## Цель продукта

Сделать современную игру в духе **Battle City / Tank 1990** (Dendy/NES): танчики, база, враги, бонусы, уровни. Первая платформа — **macOS**. Сетевая игра — в перспективе, архитектура должна это учитывать с первого дня.

Рабочее название: **Project 1990**.

## Что должно получиться (MVP → продукт)

### Игровой цикл
- Классический цикл: защитить орла/базу, уничтожить волны врагов, пройти уровень.
- Управление: клавиатура (WASD/стрелки + выстрел), позже — геймпад.
- 1 игрок; 2-й слот может занимать **ИИ-союзник** (без второго человека).
- Пауза, рестарт уровня, экран победы/поражения, меню.

### Модификации «с буквами» (расширенная версия)
Реализовать механики в духе популярных хаков/модов Tank 1990:
- враги **подбирают бонусы**;
- бонус **пистолетик** (улучшение оружия / скорострельность);
- езда по **воде**;
- **сбривание леса**;
- остальные узнаваемые фишки модифицированной версии (корабль, часы, лопата, звезда, граната, шлем и т.д. — по согласованному списку в дизайне).

Каждый бонус: чёткие правила «кто может взять», длительность, визуальный/звуковой фидбек, влияние на баланс.

### Уровни
- Порт/воссоздание **классических карт** (логика и раскладка, не копирование чужих ассетов 1:1).
- **Процедурная генерация** новых уровней:
  - играбельность: база защищена разумным периметром, есть пути, не «мусор из тайлов»;
  - логичность: вода/лес/кирпич/сталь/лёд сочетаются осмысленно;
  - **кривая сложности** растёт постепенно (плотность стали, агрессия ИИ, число врагов, редкость бонусов).

### ИИ
- Враги не «тупят»: есть цель (база / игрок / бонус / укрытие), оценка угрозы, смена тактики.
- Поведение ближе к человеческому: не ехать в стену циклами, использовать укрытия, иногда рисковать за бонусом.
- Отдельный режим: **2-й игрок = ИИ-союзник** с ролями (прикрытие базы / агрессия / поддержка).

### Аудио и графика
- Звук: **в духе** классики (выстрелы, взрывы, бонусы, фон), но только легальные источники: собственные, лицензированные или свободные ассеты. Не выдирать из ROM.
- Графика: узнаваемый top-down tank look + **современный уклон** (чёткий пиксель-арт / ретро с лёгким polish: палитра, VFX, UI, анимации). Классика как референс, не как прямой дамп спрайтов.

### Платформа и перспектива
- Сейчас: **только macOS** (сборка `.app`, запуск из инструкции).
- Позже: сетевая игра (архитектура: отдельный слой симуляции, детерминизм/репликация — заложить интерфейсы заранее).

## Архитектура (целевая)

Слои (независимо от движка):

```
┌─────────────────────────────────────────┐
│ Presentation (рендер, UI, звук, ввод)   │
├─────────────────────────────────────────┤
│ Gameplay (танки, пули, бонусы, уровни)  │
├─────────────────────────────────────────┤
│ AI (цели, поведение, союзник P2)        │
├─────────────────────────────────────────┤
│ Simulation / World (тайлы, коллизии)    │
├─────────────────────────────────────────┤
│ Services (сейвы, конфиг, аудио-шина)    │
└─────────────────────────────────────────┘
         ↑ готово к Network layer позже
```

Принципы:
1. **Игровая логика отделена от рендера** — проще тесты и будущий мультиплеер.
2. **Данные уровней** — тайловая карта + метаданные (спавны, сложность), не хардкод в коде сцен.
3. **Бонусы и модификации** — data-driven (таблицы/ресурсы), не размазанный `if`.
4. **ИИ** — чёткие цели + FSM или behaviour tree, с приоритетами.
5. **Фиксированный тик симуляции** (например 60 Hz логики) — задел под сеть.

## Стек технологий (рекомендация)

Для первой игры + macOS + тесты + задел под сеть:

| Выбор | Решение |
|--------|---------|
| **Основной** | **Godot 4** + **GDScript** |
| Почему | Быстрый старт, TileMap идеален для танчиков, экспорт macOS, встроенный мультиплеер позже, низкий порог |
| Тесты | GUT (Godot Unit Test) или встроенные тесты логики на чистых скриптах |
| Альтернатива (если хочется «чистый код») | Rust + Bevy — мощнее для сети, но сложнее для новичка |
| Не брать сейчас | Unity (лишний вес для 2D-ретро), Unreal |

Если в процессе решим иначе — зафиксировать в `README.md` и не смешивать два движка.

## Тесты — да, сразу

Писать тесты **с первого геймплейного кода**, но умно:

**Сразу тестируем (unit):**
- коллизии снаряд/тайл/танк;
- правила бонусов и таймеры;
- генератор уровней: инварианты (база существует, есть путь, лимиты тайлов);
- выбор цели ИИ (приоритеты).

**Позже (integration / smoke):**
- пройти уровень в headless-режиме;
- регрессии «нельзя проехать сквозь сталь» и т.п.

**Не тестируем на старте:** пиксель-перфект анимации, вкус саунд-дизайна.

Правило: новый модуль логики → минимальный тест на счастливый путь + 1–2 граничных случая.

## Как работать с этим промптом

При старте задачи агент/разработчик должен:
1. Назвать этап из роудмапа.
2. Сделать минимальный вертикальный срез.
3. Добавить/обновить тесты на логику.
4. Обновить README/доки при изменении установки или архитектуры.
5. Коммитить осмысленными сообщениями.
