# Project 1990 — Улучшенный промпт для разработки

Используй этот документ как основной бриф при каждом этапе работы.

## Цель продукта

Сделать современную игру в духе **Battle City / Tank 1990** (Dendy/NES): танчики, база, враги, бонусы, уровни.

- **v1 платформа:** macOS (клавиатура).
- **Стек:** чистый код — **Rust + Bevy** (без визуального редактора сцен как основы).
- **Универсальность:** архитектура сразу под будущие OS/платформы, выделенный сервер и сеть.
- **Контент v1:** **100 уровней**; дальше расширение.

Рабочее название: **Project 1990**.

## Почему Rust + Bevy

Да — для наших целей это хороший выбор:

| Требование | Как закрывает Bevy/Rust |
|------------|-------------------------|
| Чистый код, гибкость | ECS, плагины, всё в репозитории как код |
| Разные OS | Desktop (macOS/Windows/Linux) — основной путь |
| Сеть / сервер | Отдельный headless binary симуляции возможен |
| Мобилки / веб позже | Сложнее и позже; закладываем переносимую симуляцию |
| Тесты | `cargo test` на логике с первого дня |

Минус: круче порог, чем у Godot. Плюс: максимальный контроль и единый язык для клиента, ИИ и будущего сервера.

**ИИ врагов и союзника** — не отдельный движок. Это модули/системы внутри того же Bevy-проекта (ECS): цели, pathfinding, приоритеты. Один runtime, разные behaviour-профили (`EnemyAi`, `AllyAi`).

## Что должно получиться (MVP → продукт)

### Игровой цикл
- Защитить базу (орёл), уничтожить волны врагов, пройти уровень.
- Управление v1: **только клавиатура** (WASD/стрелки + выстрел). Геймпад — в бэклоге будущего.
- **Автоогонь** как в классике: удержание кнопки огня стреляет с максимальной скорострельностью текущего апгрейда; отдельная клавиша **toggle auto-fire** (вкл/выкл) — чтобы не зажимать кнопку (удобство классических портов/модов). Автоогонь не обходит лимит пуль/перегрев и уважает правила оружия.
- 1 игрок; слот 2-го игрока = **ИИ-союзник**.
- Пауза, рестарт, победа/поражение, меню.
- **Сейв прогресса** и **таблица рекордов** (несколько профилей игроков) — в продукте v1, с заделом под сеть (один формат прогресса/скора).

### Очки, жизни и мотивация скора
- Очки за уничтожение врагов (разный тип → разный вес), подбор/перехват бонусов, очистку уровня — точная таблица в `docs/SCORE.md`.
- **Жизнь за порог очков** (классика): при достижении порога (например каждые N очков, N — data) игрок получает **+1 жизнь**, с звуком/баннером; пороги и кап жизней — конфиг, с тестами.
- Доп. мотивация зарабатывать очки (v1 + задел) — см. `docs/SCORE.md`: мультипликаторы стиля, медали уровня, мягкие разблокировки, сезонные/сетевые таблицы позже.

### Модификации «с буквами» — полный набор расширенной классики
Реализуем **все** механики расширенной версии «с буквами» сразу (не урезанный минимум), включая:
- враги **подбирают бонусы**;
- **пистолетик** и апгрейды оружия;
- езда по **воде** (корабль и аналоги);
- **сбривание леса**;
- часы, лопата, шлем, граната, звезда и остальные буквенные бонусы классического мода — полный список зафиксировать в `docs/BONUSES.md` на фазе 3 и не урезать без причины.

Каждый бонус — **data-driven** (см. ниже): кто может взять, длительность, стаки, отмена, баланс.

### Свои модификации (поверх классики)
Добавить оригинальные механики, чтобы игра была свежее и лучше балансировалась. Кандидаты (утверждать на фазе 3, не обязательно все сразу):

1. **Перегрев ствола** — сильный апгрейд стреляет быстрее, но при спаме кратковременно клинит (контр к «вечному пистолетику»).
2. **Спорные ремзоны** — клетки ремонта; кто стоит — чинится; конфликт за точку.
3. **Дымовая завеса** — временно режет дальнюю стрельбу обеим сторонам (тактика, не рандом-смерть).
4. **Приманка / маяк** — бонус, который на короткое время перетягивает агро врагов на точку (спасение базы).
5. **Цепная мина** — редкий бонус; взрыв по линии или соседним врагам с риском задеть базу/себя.
6. **Общий командный бафф** — часть бонусов усиливает и игрока, и ИИ-союзника (кооп-филл).
7. **Штраф жадности** — враг, взявший 2+ бонуса подряд, коротко подсвечивается / становится приоритетной целью (читаемость + баланс).
8. **Акт «sudden death»** на последних уровнях пачки — меньше укрытий / быстрее волны (без нечестного one-shot).

Принцип баланса: каждый сильный бонус имеет **контрплей** или стоимость; поздние уровни давят **ИИ и плотность**, а не только «толще HP».

### Уровни
- Классические раскладки (логика карт) + генерация/наполнение до **100 уровней**.
- **Чем выше номер уровня — тем сильнее противник** (зафиксировано): точность, агрессия, использование бонусов, типы врагов, давление на базу. Параметры сложности — таблица по уровню (data), не магические числа в коде ИИ.
- Генерация: играбельность, логичные тайлы, постепенный рост сложности.
- После v1 — расширение за 100 (новые пачки / бесконечный режим).
- **Редактор уровней** в v1 не делаем; формат карт (файлы данных) оставляем расширяемым — задел на редактор/моды позже.

### ИИ
- Враги с конкретной целью (база / игрок / бонус / укрытие), человекоподобное поведение.
- Сложность масштабируется номером уровня (см. выше).
- ИИ-союзник (P2): роли guard / hunt / support.

### Аудио и графика
- Звук и графика **в духе** классики + современный уклон; только легальные ассеты (не ROM).
- Доступные палитры — по необходимости, в будущем.

### Платформы и перспектива

| Сейчас | Потом (архитектура не должна мешать) |
|--------|--------------------------------------|
| macOS desktop | Windows / Linux |
| Оффлайн + локальный сейв/рекорды | Сеть, выделенный **game server**, чтобы играли по сети |
| Клавиатура | Геймпад; Android / iOS; возможно Web (WASM) |

«Все могут поиграть с сервера» = клиенты подключаются к dedicated server (или браузерный клиент позже). Bevy хорошо тянет desktop; мобилки/веб — отдельные этапы, но **симуляция отделена от рендера**, чтобы не переписывать игру.

Будущее (не v1): реплеи/death-cam, редактор, геймпад, палитры.

## Что значит data-driven бонусы

Бонусы описываются **данными** (например RON/JSON/TOML), а не сотней `if bonus == Star` по всему коду.

Пример смысла:

```text
id: "gun"
letter: "G"
duration_secs: 20
who_can_pickup: [Player, Enemy]
effects: [{ type: FireRateMul, value: 2.0 }]
cancel_on: [Death, LevelEnd]
```

Код умеет «применить эффект из описания». Добавить новый бонус ≈ новый файл данных + при необходимости один новый тип эффекта — без переписывания всей игры. То же для кривой сложности уровней и (позже) баланса.

## Архитектура

```
┌─────────────────────────────────────────┐
│ Presentation (Bevy render, UI, звук)    │
├─────────────────────────────────────────┤
│ Gameplay (танки, пули, бонусы, уровни)  │
├─────────────────────────────────────────┤
│ AI (Enemy + Ally systems, одни правила) │
├─────────────────────────────────────────┤
│ Simulation / World (тайлы, коллизии)    │
├─────────────────────────────────────────┤
│ Services (сейвы, профили, рекорды)      │
└─────────────────────────────────────────┘
         ↑ Network / dedicated server later
```

Принципы:
1. Логика симуляции **без** привязки к GPU/окну — headless + тесты + будущий сервер.
2. Уровни и бонусы — data files.
3. ИИ — ECS systems + FSM/behaviour tree, параметры от номера уровня.
4. Фиксированный tick симуляции — задел под сеть.
5. Ввод = команды (не «сразу двигать спрайт»).

## Тесты — жёсткое правило (gate)

**Весь новый код логики покрываем тестами сразу.**  
**На следующий этап роудмапа не переходим**, пока:

1. тесты текущего этапа написаны и зелёные;
2. CI/`cargo test` проходит;
3. DoD этапа закрыт.

Покрываем: симуляцию, коллизии, бонусы, автоогонь/лимиты стрельбы, очки и пороги жизней, прогрессию сложности, генератор/валидатор уровней, приоритеты ИИ, сейвы/рекорды.  
Не требуем pixel-perfect тестов анимаций и «вкуса» звука — но код, который это вызывает (триггеры событий), тестируем.

## Ограничения v1

- 100 уровней; враг сильнее с ростом номера уровня.

## Как работать с этим промптом

1. Назвать этап роудмапа.
2. Сделать срез фичи.
3. Покрыть тестами; не двигаться дальше без зелёного gate.
4. Обновить README/доки при смене установки или публичных правил.
5. Коммитить осмысленно.
