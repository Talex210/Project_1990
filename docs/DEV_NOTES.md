# Заметки для первого проекта игры

Коротко: суть процесса, стек, тесты, архитектура.

## Как вообще делают игры (суть)

1. **Идея и ограничения** — что в MVP, что потом (у нас: macOS, классика + мод, ИИ, потом сеть).
2. **Вертикальный срез** — как можно раньше: танк едет и стреляет на одной карте.
3. **Итерации** — каждый цикл добавляет одну ощутимую фичу (враги → база → бонусы → ИИ).
4. **Данные отдельно от кода** — уровни, бонусы, баланс правятся без переписывания логики.
5. **Полировка в конце** — звук, UI, баланс; ядро геймплея раньше.

Не нужно сначала год писать «движок». Нужен маленький цикл: сделал → поиграл → поправил.

## Архитектура у нас

Слои: **ввод/UI/звук → геймплей → ИИ → мир/тайлы → сервисы**.  
Логика симуляции не должна знать про конкретные спрайты — так проще тесты и будущий мультиплеер.

Подробнее: [PROMPT.md](../PROMPT.md).

## На чём писать

**Выбор по умолчанию: Godot 4 + GDScript.**

| Плюсы | Минусы |
|-------|--------|
| Быстрый старт для новичка | Меньше «системного» кода, чем в Rust |
| TileMap = идеально для танчиков | Для hardcore-сети Bevy/свои решения гибче |
| Экспорт macOS из коробки | |
| Потом high-level multiplayer API | |

Альтернатива, если захочется максимально «код и сеть»: **Rust + Bevy** — осознанно сложнее.

## Тесты — можно ли сразу?

**Да.** Сразу тестируем чистую логику (коллизии, бонусы, генератор, приоритеты ИИ).  
Не гоняемся за тестами каждого кадра анимации.

Практика: новая правило геймплея → 1–3 теста. Регрессии ловятся раньше, чем «ой, сталь снова ломается».

## Звук и графика

Референс — классика 1990. Источник ассетов — **свои / свободные / заказ**, не ROM.  
Визуал: пиксель + современный polish (UI, VFX, палитра).

## Сеть «в перспективе»

Сейчас не делаем онлайн. Делаем:
- команды ввода вместо «сразу двигать спрайт»;
- фиксированный тик логики;
- состояние мира, которое можно сериализовать.

Тогда фаза 8 не потребует переписывать игру.
